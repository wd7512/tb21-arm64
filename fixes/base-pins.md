# Base image pins

Method: `tools/base_pin.py` reads the upstream image's layers from the Docker Hub API. For ubuntu and debian it takes the dated official tag whose amd64 rootfs layer equals upstream's (`exact`, pinned as `<repo>:<dated tag>@<index digest>`). For python it takes `PYTHON_VERSION` and the Debian codename from upstream's layers and pins the current index digest of `python:<version>-<codename>` (`python-exact`: same Python, the Debian point release may be newer than upstream's). `nearest` would mean no rootfs match; none was needed.
Evidence for python rows is the `PYTHON_VERSION` and the `debian.sh` snapshot date upstream recorded. `financial-document-processor` has two stages with the same base; both are rewritten and shown as one row. `break-filter-js-from-html` was already on `python:3.13.7-slim-bookworm` and gains its digest. Four tasks are not pinned: `hf-model-inference`, `mteb-leaderboard`, `mteb-retrieve` and `pytorch-model-recovery`. Their upstream images already include linux/arm64, so this repository uses those images unchanged and leaves their Dockerfiles as upstream wrote them.
